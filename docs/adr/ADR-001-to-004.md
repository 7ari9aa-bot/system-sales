# ADR-001: Money representation — Numeric(14,2) not amount_minor

## Problem
Spec §47 requires `amount_minor` (integer) + currency. Our schema stores
`Numeric(14,2)` Decimal columns.

## Decision
Keep `Numeric(14,2)` as the canonical storage. Add an `amount_minor` adapter
(integer minor units) ONLY at external edges (Stripe API, provider SDKs) via a
shared `to_minor()/from_minor()` helper in `app/core/model_kit.py`.

## Why
- PG Numeric is exact-decimal; the integer-minor rule exists to avoid FLOAT.
  We never had float money — the failure mode the spec guards against cannot
  occur with Numeric.
- Converting the 65-table schema to integers is a destructive migration with
  zero correctness gain under Numeric.
- Cross-currency analytics keep original amount + currency + rate + rate
  source (implemented in marketing analytics).

## Consequences
- All service math stays Decimal; JSON serialization emits strings.
- Any new external integration MUST convert at the edge.
- If a future engine lacks Numeric (none planned), revisit.

# ADR-002: Secrets — Supabase Vault behind SecretStorePort

## Problem
Spec §68 forbids raw secrets in business tables. `integrations.credentials`
currently stores provider credentials as plain JSONB.

## Decision
Introduce `SecretStorePort` (application contract) with a Supabase Vault
adapter. `integrations.credentials` becomes `{secret_ref, metadata}` only.
Rotation metadata (created/rotated/expires/status/version) lives beside the
reference. Migration: read→vault-write→replace job (W6), required BEFORE
storing production WhatsApp tokens.

## Consequences
- All credential reads go through the port (cache per-request, never persist
  plaintext).
- Vault access is audited; rotation never breaks in-flight requests
  (dual-reference window).

# ADR-003: API versioning — /api/v1 mount now

## Problem
Spec §78 requires versioned routes; current routers are root-mounted.

## Decision
Mount the entire app under `/api/v1` via a parent router in `main.py`. Legacy
root paths get a deprecation shim (redirect 307) for one release cycle.
Frontend api.ts updated in the same wave.

# ADR-004: Pagination — cursor-based

## Decision
`limit/offset` replaced by opaque cursor (`created_at+id` keyset) via shared
helpers; responses carry `{items, next_cursor}`. Offset stays only on small
admin tables (<10k rows, immutable order).
