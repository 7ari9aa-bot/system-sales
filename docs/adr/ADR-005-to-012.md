# ADR-005: SSE Authentication — ?token= Query Param Fallback

## Problem
The realtime SSE gateway (/api/v1/realtime/events) requires authentication, but the
browser's native EventSource API cannot send custom headers (including Authorization: Bearer).

## Decision
The SSE endpoint (realtime/router.py) uses a dedicated _sse_auth dependency that:
1. Tries Authorization: Bearer <token> header first (standard, used by API clients/tests).
2. Falls back to ?token=<access_token> query parameter for browser EventSource connections.

The token is excluded from OpenAPI schema (include_in_schema=False).

## Consequences
- Tokens in URLs end up in access logs. Log redaction rules MUST scrub ?token=.
- Future: Replace with a short-lived one-time SSE nonce (ADR-042).

# ADR-006: Multi-Tenancy — PostgreSQL RLS + Session GUCs

## Decision
Primary isolation: PostgreSQL Row-Level Security (RLS) policies on every business table,
controlled by the app.tenant_id session-level GUC.

bind_tenant(session, tenant_id) executes SET LOCAL app.tenant_id = <uuid> inside the
current transaction. The SSE gateway double-checks meta.tenant_id on every event.

## Consequences
- Missing bind_tenant call results in empty result sets (fail-closed).
- Platform-admin queries need SECURITY DEFINER functions.

# ADR-007: Domain Events — Redis Streams Outbox Pattern

## Decision
All cross-domain side effects go through Redis Streams using the transactional outbox pattern:
1. Domain service writes event to outbox_events table inside its DB transaction.
2. OutboxRelayWorker tails outbox_events, publishes to Redis Stream.
3. Consumers (StreamWorker subclasses) read from Redis Streams using XREADGROUP.

At-least-once delivery: consumers MUST be idempotent.

# ADR-008: Payments — Stripe + Unknown State Reconciliation

## Decision
Two-phase approach:
1. POST /billing/checkout creates payment_intents row with status=pending_redirect.
2. Stripe webhook updates the row to succeeded | failed | refunded.
3. Scheduled job (reconcile_payments) runs every 15 min for stuck intents.

pg_try_advisory_xact_lock prevents duplicate processing in multi-pod deployments.

# ADR-009: AI Budget Enforcement — Hard Cap Before Each Call

## Decision
Every AI model call goes through enforce_budget() in ai/gateway.py before any provider call.
Resolution order: agent-level BudgetPolicy > tenant-level BudgetPolicy > MONTHLY_BUDGET_CAP = USD 50.
on_exceed=block raises RateLimitExceededError (HTTP 429). on_exceed=warn logs and continues.

# ADR-010: Global Search — SearchPort Abstraction

## Decision
core/search.py defines SearchPort (abstract base) and PostgresSearchAdapter (default).
GET /api/v1/search?q=<query>&limit=<n> returns unified hits across customers, orders, products, conversations.
The port pattern allows swapping pg_trgm -> pgvector -> Typesense without changing the router.

# ADR-011: Notifications — Unified Model in platform.models

## Decision
The canonical Notification ORM model lives only in app/modules/platform/models.py.
app/modules/notifications/models.py re-exports it as an alias.
Fields added in W8 migration: title, action_url, payload (JSONB).

# ADR-012: Privacy — Data Erasure via Consent Ledger

## Decision
GDPR Art. 17 erasure requests create a ConsentRecord audit row, then schedule an
anonymize_customer job that replaces PII with anonymized placeholders.
Never hard-deletes rows; preserves referential integrity and financial audit trails.
