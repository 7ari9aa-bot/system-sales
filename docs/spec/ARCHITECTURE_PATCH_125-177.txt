# §125 — TENANT CONTEXT FOR ALL EXECUTION MODES

Tenant context ليس خاصًا بالـHTTP.

يجب أن يكون موحدًا لكل execution path:

```text
HTTP Request
Webhook
Worker
Outbox Relay
Redis Consumer
Scheduled Job
n8n Callback
AI Run
Maintenance Job
Billing Job
Retention Job
Analytics Job
```

كل execution يحصل على:

```text
tenant_id
workspace_id
location_id
actor_id
correlation_id
```

## Worker / Consumer

أي job/event tenant-scoped:

```text
Job
↓
Resolve tenant context
↓
Open transaction
↓
Set transaction-scoped tenant context
↓
Execute under RLS
↓
Commit
```

## Cross-tenant jobs

مثل:

```text
Billing
Retention
Analytics
Maintenance
```

تعمل:

```text
Enumerate tenants
↓
Tenant A transaction
↓
commit
↓
Tenant B transaction
↓
commit
```

ولا تستخدم transaction واحدة لكل tenants.

## Webhook ingress

الـWebhook يأتي قبل معرفة الـtenant.

لذلك:

```text
Webhook
↓
Verify signature
↓
Lookup provider_account/channel_account
↓
Resolve tenant
↓
Enter tenant-scoped business path
↓
RLS-protected processing
```

الـlookup نفسه يكون عبر **ingress mapping** ضيقة الصلاحيات، وليس bypass مفتوحًا لقاعدة البيانات.

# §126 — CONVERSATION SERIALIZATION

كل Conversation لها processing serialization key:

```text
conversation_id
```

ممنوع تشغيل أكثر من state-mutating AI/message processor لنفس conversation في نفس الوقت.

استخدم:

```text
conversation lease
+
fencing/version
```

مثال:

```text
Message A
Message B
Message C
```

لا تصبح:

```text
AI A ──────┐
AI B ──────┼── parallel writes
AI C ──────┘
```

بل:

```text
Conversation Queue
↓
Acquire lease
↓
Process next event
↓
Commit
↓
Release / renew
```

## Conversation ownership state

يجب أن تكون صريحة:

```text
AI_ACTIVE
HUMAN_ACTIVE
PAUSED
HANDOVER_PENDING
CLOSED
```

## Newer-message policy

لو AI Run قديم ما زال يعمل ووصلت رسالة أحدث:

```text
older run
→ mark stale/cancelled where possible
```

ولا يسمح له بإرسال stale response بعد أن أصبح السياق قديمًا.

لو Human تدخل:

```text
Human response
→ AI outbound run becomes stale
```

# §127 — CONSUMER IDEMPOTENCY

"Consumer يجب أن يكون idempotent" ليست implementation.

استخدم:

```text
processed_events
```

أو equivalent inbox table:

```text
ProcessedEvent
├── consumer_name
├── event_id
├── processed_at
├── result_reference
└── status
```

مع unique constraint:

```text
(consumer_name, event_id)
```

والأهم:

```text
BEGIN
    insert processed_event
    apply business effect
    update domain
COMMIT
```

أي يتم تسجيل processing marker والـeffect داخل نفس transaction عندما يكون ذلك ممكنًا.

# §131 — PII / DATA-LIFECYCLE MAP

أي data copy يجب أن تكون معروفة:

```text
Primary DB
Outbox
Event Log
Audit
Logs
n8n
Search Index
Vector Store
Analytics Read Models
Object Storage
Backups
```

لا نضع PII كاملة في كل layer.

القاعدة:

```text
Events
→ IDs + minimal metadata

Logs
→ no raw PII by default

Audit
→ minimum necessary before/after

Search
→ deletable derived index

Vector store
→ deletable derived data

n8n
→ minimum payload + retention policy
```

يجب أن توجد:

```text
Data Classification Map
Retention Policy
Deletion Propagation Policy
```

أي:

```text
Customer deleted
↓
Primary records
↓
Search index
↓
Vector chunks
↓
Analytics derived data
↓
Memory
↓
n8n retained data
↓
Other derived stores
```

كلها تدخل في deletion workflow حسب policy.

Backups لها retention منفصل ومعلن.

# §136 — N8N VS INTERNAL WORKFLOW

```text

= Canonical Workflow Definition
```

```text

```

```text

↓

↓
Our Workflow Version
↓
Execution Policy
↓

```

n8n ليس source of truth للـtenant workflow.

## n8n isolation

الـtenant credentials لا تكون داخل workflow definitions كنصوص raw.

تستخدم:

```text

```

والـn8n callback إلى FastAPI يستخدم:

```text

+

```

ولا يملك token global unrestricted.

# §177 — FINAL NON-NEGOTIABLE RULES

```text
1. Tenant context exists outside HTTP too.
2. RLS protects every tenant-scoped DB path.
3. AI never bypasses Application/Domain rules.
4. Every side effect is idempotent.
5. Every critical mutation is auditable.
6. Conversation processing is serialized.
7. Outbound messaging is stateful and reconcilable.
8. Outbox is not the permanent event archive.
9. EventLog is durable replay history.
10. Redis is transport, not business truth.
11. Modules cannot access internal repositories directly.
12. Read models may join through dedicated query/read architecture.
13. Long business processes use explicit state machines/process managers.
14. n8n is never core business truth.
15. Untrusted AI input is never trusted as instructions or authorization.
16. AI tools are server-side scoped to the actual conversation/tenant.
17. High-risk AI actions require durable human approval.
18. Customer PII has a complete lifecycle map.
19. Derived data must participate in deletion/retention policies.
20. Search/RAG/Memory are tenant- and permission-scoped.
21. Provider events can arrive late/out of order.
22. Conversation lifecycle is explicit.
23. All scheduled work is durable.
24. Entitlements are centrally enforced.
25. Metrics have one canonical definition.
26. Realtime supports reconnect and authorization revalidation.
27. Platform Admin is separate from Tenant Admin.
28. External stores require explicit source-of-truth policies.
29. Tenant-specific recovery is different from full-database DR.
30. Production rollout requires evaluation, observability, and rollback.
```
